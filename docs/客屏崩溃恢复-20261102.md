# 客屏意外退出恢复

日期：2026-11-02（Asia/Shanghai）。基线包含 Kiro 的开场自检 `a5b6c61`；本轮继续在 `codex/karaoke-handoff-20261102` 开发。

## 行为

此前客屏子进程退出时，控制器仅清空进程对象并置 `outputOpen=false`，没有恢复入口提示。本轮在原输出管理中增加有限恢复：

- 非零退出码（包括被信号终止）或启动失败后，按 1、2、4 秒退避，最多自动重开三次。第四次失败停止自动恢复，现场与开场自检显示原因，可手动重新打开。
- 输出进程连续存活一分钟后恢复重试额度。反复启动即退出不会无界循环。
- 从主界面关闭、等待期间取消、客屏窗口关闭或 Esc 导致的正常退出码 0，均保持关闭。退出主程序先取消待重试。
- 独立客屏与 Serato 透明叠加共用此规则。切换输出类型会取消旧重试；自检里的「重新打开」沿用当前类型，不强制改为独立客屏。
- 重开继续读取当前 `program.json`，沿用当前来源、人工隐藏、同步偏移、样式与显示器目标。当前播放位置仍由原接入和时效检查决定，不恢复旧观测。
- 状态区保留原按钮和快捷键，恢复期间仍可点「关闭客屏 / 关闭 Serato 字幕」或按 Ctrl+Shift+O 取消。没有新增确认弹窗。

`outputOpen` 仍只表示输出子进程已经启动，不能证明它已在电视显示。当前未做进程无响应检测；主程序自身崩溃、重开后的现场输入恢复也不属于这一批。
