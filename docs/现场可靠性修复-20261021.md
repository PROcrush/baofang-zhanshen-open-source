# 现场可靠性修复 · 2026-10-21

用户要求修复待复核提示、全局隐藏歌词、重新连接和单双行快捷切换，保持简单好用。基于 `38337cdf36713bd099b37762bf098fcfb2b21516`，本轮只处理这四项及验证中直接发现的文字组件空引用。

## 使用变化

| 场景 | 现在的行为 |
| --- | --- |
| 有歌词缓存，但文字仍待复核 | 现场顶部和对应盘显示橙色“歌词待复核”，提供“复核歌词”入口，进入歌曲准备 |
| 去样式、准备、曲库或制作页面 | 顶部始终可隐藏/恢复现场歌词；Ctrl+H 在主应用所有页面可用 |
| 读取进程仍运行，但播放数据不更新 | 再次连接会停止旧接入、清掉旧观测，并重新等待新数据 |
| 单行预设后点击“双行歌词” | 同时切换行布局与输出模式，实际画面和按钮选中态一致 |

有效的待复核缓存继续按原规则显示，不自动阻断演出，也不把“已缓存”标成“已复核”。隐藏保留此前自动或人工来源，恢复仍受来源、版本、时钟与歌词有效性约束。切页不恢复歌词，制作预览不受现场隐藏影响。

## 实现与错误恢复

### 审阅状态

`app/storage.py` 的 `timeline_needs_review` 统一曲库与现场的审阅判断：`correction.status=needs_review` 或非空 `correction.review` 都显示待复核；兼容不存在审阅元数据的旧缓存。

`project_state` 将 `needsReview` 和明确的缓存文案传给对应盘；来源没有有效观测时清除该提示，让连接/失效信息优先。来源选择和字幕渲染门槛不因提示而改变。`LivePanel` 的提示和复核入口，以及 `DeckCard` 的颜色与文案使用同一状态。

### 跨页隐藏与恢复

隐藏快捷键从现场子页面移到 `Main.qml`，避免切页失效和同一快捷键重复注册。现场保留下方固定按钮，其余页面在导航右侧提供“隐藏现场歌词 / 恢复现场歌词”。沿用控制器的隐藏和恢复方法，保留原来源。

macOS 的 Qt 默认将逻辑 Control 映射到 Command。本轮原生实测发现该差异，因此 macOS 使用 Qt 的 Meta 映射匹配界面承诺的实际 Control+H；其他系统保留 Ctrl+H。没有注册系统级热键，也不承诺在其他应用获得焦点时触发。

### 重新连接

已在 Serato 模式时，`connectSerato` 先停止并排空旧接入，再清除旧 epoch、序号、推子有效期、自动选盘历史、盘观测及读取诊断，重新启动只读接入。只有新观测通过现有校验后，才恢复可用状态。

隐藏状态、隐藏前来源、每首歌的同步偏移和已打开的输出保留；不发送 DJ 播放指令。旧进程无法停止时不重复启动，提示重试或查看诊断。连接中的说明和失败原因直接出现在现场提示区。

### 单双行切换

`setLiveLayout` 一次保存两项关联设置：双行为 `lineMode=double`、`outputMode=standard`；单行大字为 `lineMode=single`、`outputMode=dynamic`。按钮选中态按渲染器实际采用的“动态模式或单行布局”判断。字体、字号、配色、亮度和高亮方式保留。

保存失败时恢复原来完整布局，不出现改了一半的设置；提示“字幕布局未保存”。重试成功后清除这条错误提示。

界面检查还发现渐变文字组件退出时，子项已销毁却继续读取 `lineCount/textHeight` 的空引用。`LyricText.qml` 增加空值保护，最终重新检查时没有该错误输出。
