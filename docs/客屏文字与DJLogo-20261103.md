# 客屏文字与 DJ Logo

## 艺术模板与输入（2026-11-07）

在“现场 → 客屏内容 → 喊话 / DJ 标识”打开「模板」。银弧序幕用冬青黑体 W3，标题左置，和上方 Logo 留出间距。赤月舞台用宋体 Black，红月在左，标题贴右并压低。唱片切片用黑体 Medium，字卡放在上方居中。经典描边继续可选。Logo 可选原图角标、银线署名和舞台侧光。上方艺术模板给传统 KTV 歌词留出下半屏。

文字在同一行选择模板和显示时长。「调整位置 / 外观」里可以单独切换字体和九宫格位置。字体跟随文字保存，也会随历史和配置包复用。缺少字体字段的旧设置使用模板字体，保留保存的位置。生日常用语会把光标放在姓名栏。Logo 可拖入一张本机图片，也可点击「选择图片」，推荐透明 PNG。未填文案或未导入 Logo 时可看模板示例。切换模板保留文字或图片，选定后先看「待上屏」，确认才发布。

- Apple 的排版案例将字号、字重和行距作为一组参数来组织层次，布局指南也说明了左上起读与对齐的作用。银弧采用较轻的冬青黑体并留出左边距，用原创冷光维持焦点。[Apple 排版讲座](https://developer.apple.com/videos/play/wwdc2020/10175/) · [Apple 布局指南](https://developer.apple.com/design/human-interface-guidelines/layout)
- Stageco 的舞台图文显示，The Weeknd 的 After Hours Til Dawn 巡演把月亮放在延伸舞台边缘。赤月借鉴把视觉重心放在一侧的做法，右侧宋体 Black 是这款中文模板自己的字体选择。[Stageco 舞台记录](https://www.stageco.be/nl/references/the-weeknd-after-hours-til-dawn-2022/584) · [TAIT 舞台案例](https://www.taittowers.com/work/after-hours-til-dawn-tour)

日期：2026-11-03。用户要求先放下 rekordbox AX 接入，增加客屏输入文字和 DJ Logo 图层。

## 当前使用（DJ 操作方案已实现，源码版）

后续新增的“我的 → 常用语 / 历史 / 配置包”及 schema 2 存储说明，见 [DJ 常用语与配置](DJ常用语与配置-20261103.md)。

现场工具栏与右侧标签统一“客屏内容”，在右侧原位提供“喊话 / DJ 标识 / 祝福”，不再用图层大弹窗遮挡 A/B 接管。中间预览可切换“现场画面 / 待上屏”；草稿仅本机可见，明确发布才更新独立客屏或透明叠加。未开客屏时说明仅本机预览。

- 喊话：最多 300 字、支持换行；欢迎、生日、感谢、返场模板先填草稿，生日模板填姓名后才能发布。默认 15 秒，也可选 30、60 秒或明确标注重启保留的固定显示。回车换行，输入区 Control+Enter 发布；面板底部直接上屏、撤下，切换标签不丢草稿。
- DJ 标识：选择 PNG / JPG / WebP 导入本机副本，先预览，点击显示 / 更新才上屏；可直接隐藏并再次显示，移动原图片不影响输出。
- 布局：上方喊话、居中欢迎及左上 / 右上角标预设；位置、大小、不透明度与字色在细调中，均先预览再整体发布。预览歌词避让线不上客屏，右上角标与二维码碰撞会提示。
- 祝福：同一 Wi-Fi 扫码发送，DJ 审核后显示 15 秒，与喊话互相替换、一次一条；待审内容优先展示，二维码与设置单独展开。发布失败保留待审项。
- 撤下全部：一起隐藏文字、Logo、祝福及二维码，保留素材、草稿、待审项与服务，不改变歌词来源。配置保存失败时仍更新运行画面并提示；这不保证整块磁盘或输出状态通道不可写时仍能送达客屏。

临时喊话保存为隐藏配置，重启保留上次发布文字作为草稿而不重放（未发布编辑只在本次打开期间保留）；单调时钟期限同时由主程序和独立客屏执行，主程序停止刷新时仍会到时撤下。固定文字和标识保存其显隐。现场内容不写入制作导出；完整数据备份包含素材，歌词库备份与当前搬家包不包含。

以下首版及第二轮记录用于回溯，交互以本节和最新使用手册为准；此前暂存包均不包含本轮变更，仍暂缓重新封包。

## 实现与维护

- `app/screen_layers.py`：严格字段和范围校验；`runtime/screen-layers.json` 原子保存；图片最多 20MB / 1600 万像素 / 单边 8192，以 PNG 保存到 `runtime/screen-assets/{sha256}.png`。保留原图片，移除只清空引用。
- `app/controller.py`：保存成功才替换现场状态；文字草稿不提前上屏；失败原位提示。主控制器启动读取设置；独立 `FileController` 重新根据本机资产生成 URL，不采用快照中的外部地址。
- `ui/ScreenLayers.qml`：共用图层、安全边距、长文本适配、图片比例及透明度；`ScreenContentPanel.qml`：草稿、本机预览、发布及撤下；`GuestWishControls.qml`：扫码和审核。旧 `OutputLayersPopup.qml` 已移除，样式缩略图排除图层。
- 不修改 AX 接入、DJ 音频或系统权限。完整应用数据备份包含图层；歌词库备份和当前搬家包不包含，使用搬家包换机后重新输入 / 导图。

### 第二轮功能补测，暂不封包

按用户“慢慢测试功能再打包”的要求，先补边界和恢复检查，未重建或验收安装包。此前基于 `2df231e` 生成的暂存归档不含以下修复。

本轮发现并修复：

- emoji 原先按 UTF-16 长度计数，300 个耳机 emoji 在界面被计为 600 字，无法上屏。改为按 Unicode 码点计数，与后台 300 字限制一致；本机 Qt 的 `Array.from` 仍按码元拆分，因此显式合并代理对。实际按钮测试确认 300 个可上屏、301 个禁用。
- 极多换行时 `Text.Fit` 到达最小字号后仍可能溢出。例如 1080p 中 150 行实测绘制高度 2850px，安全区域仅 982.8px。增加按选定对齐原点缩放的兜底；保留完整文本和换行，正常文本不受影响。对齐位置和实际像素边界一起核对，避免只测布局尺寸而漏掉底部裁切。

新增 `tools/check_screen_layers_edges.py`，隔离 Qt 检查通过：中文输入法预编辑/提交事件、回车换行不自动上屏、输入同步快捷键字符不触发校准；Logo 九个位置 × 三档不透明度的实际 RGBA、透明边缘和比例；640×420 / 1920×1080 / 3840×2160 下九个位置的长中英文、150 行及大量空行布局与像素边界；JPG / WebP 解码、透明图片，取消选图与坏图、尺寸/文件大小超限、缺失文件保留旧 Logo。QML 警告 0。输入法事件模拟不等于所有真实 macOS 输入法均已验收。

`tools/check_output_recovery.py` 增加文字 / Logo：实际启动源码版客屏子进程并终止，自动重开后检查快照状态、Logo 颜色与中央文字像素一致，确认不是仅恢复状态却画面空白；主动关闭、取消重试、连续失败上限、退出清理一并通过，QML 警告 0。原有 `tools/check_screen_layers.py` 也重新通过。
