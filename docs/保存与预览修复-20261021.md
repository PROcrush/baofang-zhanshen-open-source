# 保存与预览修复 · 2026-10-21

本轮完成上次用户体验审查的第一批修复：歌曲工程保护、改词保存、编辑后的旧视频预览。沿用简洁双栏与传统 KTV 外观。

## 用户操作变化

### 制作下一首

- 原“换歌”入口改为“制作下一首”。选择不同音频后建立新的工程身份，首次保存选择新位置，不会沿用上一首工程的保存目标。
- 上一首有未保存修改时先写恢复副本，界面提供“恢复修改”。恢复副本无法写入时，保留原工程与撤销记录并说明原因。
- 重选同一个未改变的音频文件不清空歌词。新工程沿用当前字形设置和背景，清空旧歌词、编排和分析；历史撤销不跨工程。

### 保存正在修改的歌词

- 改词框存在草稿时，“已保存”变为“保存进度”。
- 顶栏保存、⌘S、另存、⌘⇧S 和导出会先提交正在编辑的歌词。更多编辑中的保存与视频导出使用同样处理。
- 空文本或超过 10000 字的输入不能提交，草稿继续留在编辑框中，文件不改写，导出不启动。局部“保存修改”同样在验证成功后才退出编辑。
- 制作下一首、打开工程及切换编辑视图前提交有效草稿，使恢复副本包含当前歌词。
- 既有时码规则不变：同字数替换保留词区间，增删文字降为句级时间；逐句扫色状态的进一步优化属于第二批工作。

### 查看上次导出

- 当前渲染 URL 与上次保存的视频 URL 分开保留。修改歌词或样式会使当前结果失效，但不删除上次成片。
- 修改后显示“有新修改，需重新导出”，按钮改为“查看上次视频”。实际播放上次保存文件，画面下方注明尚未包含当前修改。
- 返回编辑入口保持可见。源歌曲正在播放时，先暂停源歌曲再切到旧视频，避免状态回调立即关闭视频。
- 切换歌曲或重新打开工程时清除其他工程的临时成片入口。旧成片文件仍保留。

## 导出进程初始化修复

本轮自动界面验证与桌面导出分别遇到一次子进程异常。新增本地 `engine-failure.log` 后，桌面日志明确记录 `Could not find the Qt platform plugin "offscreen"`。检查发现 Qt 的平台插件目录和动态库重新带有 `UF_HIDDEN` 标记，主程序启动时的修复不能覆盖稍后启动的渲染进程。

渲染进程在创建 QGuiApplication 前调用项目已有的 `repair_qt_metadata()`，只清除本项目 `.venv` 内的隐藏标记，不修改文件字节或其他标记。补充回归会主动给离屏插件及目录加隐藏标记，再通过真实导出进程生成 MP4，并核对插件摘要不变。引擎异常的退出状态、标准输出和错误输出只写入本机任务目录，便于排查，不上传运行日志。
