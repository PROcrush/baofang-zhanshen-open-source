# 公网扫码祝福

部署公网祝福服务后，打开“现场 → 客屏内容 → 祝福 → 公网扫码（支持手机流量）”，把二维码放到客屏。客人用 4G/5G 或任意能访问该地址的网络打开祝福页。打碟电脑也需要能访问这个 HTTPS 地址，可以和手机用不同网络。每条祝福仍由 DJ 审核，点“上屏 15 秒”后才显示。

公网断线时，软件收起二维码并尝试重连。短时间内恢复会继续用同一张码。关闭服务或中继判定该场次已过期后，旧码失效。手动关闭会清空本机待审列表。无公网服务或开启“离线演出”时，可用“局域网扫码”。

## 给部署人员

公网中继只处理临时场次和祝福文字。队列保存在内存，单个场次最多排队 50 条。打碟端每 2 秒收取，45 秒没有收到打碟端的有效轮询，场次即失效。服务器重启后需要重新开码。客人链接只有提交权限，待审列表和关闭操作需要打碟端私有凭据。

1. 准备能被目标客人手机和打碟电脑访问的域名及 HTTPS 证书。由反向代理负责 HTTPS，Python 中继只监听服务器的回环地址。
2. 在服务器的 Python 虚拟环境安装 Gunicorn。在服务进程环境中设置 `BAOFANG_WISH_RELAY_KEY`，使用 `python3 -c 'import secrets; print(secrets.token_urlsafe(32))'` 生成随机值，妥善保存。从源码目录启动：

   ```sh
   gunicorn --workers 1 --threads 8 --bind 127.0.0.1:8765 'app.wish_relay:create_app()'
   ```

   保持一个 worker 和一个实例，多个进程各自持有不同的内存队列。代理应覆盖客户端提供的 `X-Real-IP`，使用实际连接 IP，并关闭带二维码路径或请求凭据的访问日志。例如直接面向手机和电脑的 Caddy 站点：

   ```caddyfile
   wish.example.com {
       request_body {
           max_size 2KB
       }
       reverse_proxy 127.0.0.1:8765 {
           header_up X-Real-IP {remote_host}
       }
   }
   ```

3. 在启动桌面开发版的环境里设置相同的 `BAOFANG_WISH_RELAY_KEY`，将 `BAOFANG_WISH_RELAY_URL` 设为该站的 HTTPS 根地址，例如 `https://wish.example.com`。重新启动开发版即可开启公网扫码。可在终端交互输入密钥，避免把它写入命令历史：

   ```sh
   export BAOFANG_WISH_RELAY_URL=https://wish.example.com
   read -rs 'BAOFANG_WISH_RELAY_KEY?输入公网祝福服务密钥：' # macOS 默认 zsh
   export BAOFANG_WISH_RELAY_KEY
   .venv/bin/python -m app.main --live
   ```

4. 在包房开码后，用一部关闭 Wi-Fi 的手机扫客屏，提交一条测试祝福，确认待审、手动上屏和关场后旧码失效。公网服务上线前需按实际场地和目标手机网络复验。

## 本地验证

```sh
.venv/bin/python -m unittest discover -s tests -p 'test_wish_relay.py'
.venv/bin/python -m tools.check_wish_public
```

界面检查会在回环地址启动临时 HTTPS 服务，用测试证书和合成祝福验证手机页、DJ 待审、上屏、断线恢复及关场。测试证书只在检查进程中信任，检查结束后删除。
